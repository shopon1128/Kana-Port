About

10×10のマス目の上で、6種類の駒を動かして相手を全滅させたら勝ちのターン制ボードゲームです。 駒は1ターンに配られる4のMPを共有していて、移動も攻撃も1マスにつき1消費します。 1体を4マス走らせるのか、4体を1マスずつ動かすのか、 限られたMPをどの駒に割り振るかが毎ターンの判断になります。

駒は「つかんで動かす」操作です。カーソルを合わせてSpaceでつかむと、 その駒が行けるマスと手を出せる相手が即座に盤面に出ます。 攻撃した駒はそのターン中もう動かせなくなるので、 どの駒から動かすかという順番も重要です。

Jobs

各プレイヤーは6種類の駒を1体ずつ持ちます。 HPの差と移動の癖が噛み合うように、役割を散らしています。

6ジョブの性能（HPは初期値）
ジョブHP特徴
Sword3 MPが2以上残っていれば、2消費して2ダメージの強攻撃になる
Knight4 最もHPが高く、上下左右に隣り合った味方が受けるダメージを肩代わりする
Archer2 進もうとしたマスの隣に敵がいると、移動せずその場から攻撃する。
Magician2 縦方向の移動を1ターンに2回までMPなしで行える
Doctor3 味方のHPを回復できる
Van3 横方向の移動を1ターンに2回までMPなしで行える

画面の見方

このゲームは、駒ごとに移動の癖も攻撃の届く範囲も違います。 それを覚えないと遊べない状態にしたくなかったので、 「今この駒に何ができるか」をすべて盤面の色で示すようにしました。 駒をつかんだ瞬間に、以下が同時に出ます。

  • 行けるマス残りMPで到達できる場所。他の駒がいるマスは通れないので、囲まれていれば狭くなります
  • MPを使わずに行けるマス一部のジョブの能力で無料移動が届く範囲。同じ緑のまま明るさだけを変えて、お得感を出すようにしてます
  • 攻撃できる相手今いるマスから手が届く敵。弓兵の変則的な射程もここに出るので、覚えていなくても分かるようにしました
  • 回復できる味方Doctorの回復ができる相手を指してます
  • 肩代わりの効果範囲knightの肩代わりの効果範囲がわかりやすくなるように、常に表示しています
  • 行動済みの駒攻撃を終えてそのターンもう動かせない駒は暗くなります

残りMPは画面上部の丸4つで示しています。 残量がぱっと見で分かりやすい形にして、視線の動く先である盤面のすぐ真上に置きました。 丸の色がそのまま手番の色で、待機側の表示は暗く落としてあります。

Design

設計するにあたって決めたことです。それぞれ、下の Code にあるファイルと対応しています。

表示と実際の操作で、同じ判定を通す

盤面の「攻撃できる相手」の枠と、方向キーを押したときの実際の処理は、 どちらも ResolveMove という同じ関数に「このキーを押したら何が起きるか」を確認しています。 表示用と操作用で判定を別々に書くと、片方だけ直したときに「光っているのに攻撃できない」ずれが起きるためです。 行けるマスの計算も、Archerが敵の隣に踏み込めない判定や移動コストは同じ部品を使っています。 （MoveRules.hpp / MoveRules.cpp）

無料移動を含めた到達範囲を、正しく出す

MagicianとVanは1ターンに2回まで無料で動けるので、歩数だけでは行ける範囲が決まりません。 同じマスでも、無料移動を使い切って着いたか残して着いたかで、その先に行ける距離が変わるからです。 そこで「マス」と「無料移動を何回使ったか」の組を1つの状態として、最小の消費MPを探索しています。 1歩のコストは0か1しかないので、両端キューを使う0-1 BFSで求めています。 明るい緑（MPを使わずに行けるマス）もこの結果から出しています。 （MoveRules.cpp）

ジョブの違いは「上書き」だけで表す

元のコードは name == "doctor" のように、ジョブ名の文字列で分岐していました。 作り直しでは、攻撃コスト・移動コスト・回復できるか・肩代わりするか、といった能力を基底クラスの仮想関数にし、 各ジョブは自分の違いだけを上書きしています。 移動や攻撃の判定はジョブ名を一切見ないので（名前はログの表示にだけ使います）、ジョブを足しても判定のコードは触りません。 移動コストが「無料移動を何回使ったか」を引数で受け取るのは、到達範囲の探索で「もし2回使っていたら」を試算するためです。 （Jobs.hpp）

描画は、ゲームの状態を読むだけにする

描画クラスはゲーム本体を知らず、HudState という受け渡し用の値と盤面を、読み取り専用で受け取って絵にするだけです。 また描画先をウィンドウに固定せず sf::RenderTarget に対して描いているので、同じ絵を画像ファイルにも出せます。 ゲームを起動しなくても画面を画像で確認できるので、配色やレイアウトはこれを見ながら詰めました。 （Renderer.hpp）

色は「今できること」にだけ使う

数値と色はすべて1つのファイルに集め、ルール・見た目・リソースに分けています。 色は「行ける」「攻撃できる」「残りMP」のように今とれる行動にだけ使い、 Knightの肩代わり範囲のように「今そうなっているだけ」の情報は灰色に抑えました。 攻撃の枠を赤ではなくオレンジにしたのは1Pの駒の赤と紛れないため、といった理由も、コメントとしてその場に残しています。 （Config.hpp）
